# SEMI 백엔드 — 로컬 서버 구동 및 접속 방법

> 대상: `정찬성/semi-backend/` (FastAPI + PostgreSQL 16 + 산탄데르 데이터 탐색 대시보드).
> 기술 스택 근거: `정찬성/1. 기술 스택/1. 기술 스택(신규).md` · 대시보드 설계: `정찬성/99.TRD설계서_바이브코딩/SEMI TRD_메인화면.md`

## 0. 사전 준비물

| 항목 | 확인 방법 |
|---|---|
| Python 3.12~3.14 | `python --version` |
| Docker Desktop (실행 중이어야 함) | `docker --version`, `docker compose version` |

## 1. 최초 1회만 하는 설정

이미 `semi-backend/.venv`, `.env`가 만들어져 있다면 이 단계는 건너뛰고 §2로 간다.

```powershell
cd 정찬성\semi-backend

# 1) 가상환경 생성 + 활성화
python -m venv .venv
.venv\Scripts\activate

# 2) 의존성 설치 (개발용 포함)
pip install -e ".[dev]"

# 3) 환경변수 파일 생성
copy .env.example .env

# 4) 개인정보 암호화 키 발급 → .env의 FIELD_ENCRYPTION_KEY=에 붙여넣기
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

`.env`는 `.gitignore`에 포함돼 있어 git에 올라가지 않는다. 팀원마다 각자 로컬에서 위 과정으로 새로 만들어야 한다.

## 2. 서버 구동 순서 (매번 반복)

### 2-1. PostgreSQL 컨테이너 기동

```powershell
cd 정찬성\semi-backend
docker compose up -d
```

⚠️ **이 개발 환경은 기본 포트 5432가 다른 컨테이너(`toyo-db`)에 이미 점유돼 있어서**, `.env`에서 `POSTGRES_PORT=5555` / `DATABASE_URL`도 포트 5555로 맞춰뒀다. `docker compose up -d`가 "port is already allocated" 에러를 내면 §5-1을 본다.

정상 기동 확인:

```powershell
docker compose ps
# STATUS 열이 "Up ... (healthy)" 이어야 함
```

### 2-2. DB 마이그레이션 (스키마가 바뀌었을 때만)

```powershell
.venv\Scripts\activate
alembic upgrade head
```

현재 단계(1단계 기반 구조)에는 실제 도메인 테이블이 없어 `alembic_version` 테이블만 생성된다 — 정상이다. 도메인이 추가된 뒤에만 실질적인 테이블이 생긴다.

### 2-3. 웹 서버 실행

```powershell
.venv\Scripts\activate
uvicorn app.main:app --reload
```

아래와 같은 로그가 뜨면 정상이다.

```
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
INFO:     Application startup complete.
```

## 3. 접속 방법

서버가 떠 있는 동안 브라우저에서 아래 주소로 접속한다.

| URL | 내용 |
|---|---|
| http://127.0.0.1:8000/health | 서버 생존 확인용(`{"status":"ok"}`만 반환) |
| http://127.0.0.1:8000/docs | FastAPI 자동 생성 API 문서(Swagger UI) — 모든 엔드포인트를 여기서 직접 호출해볼 수 있다 |
| http://127.0.0.1:8000/dataviz | **산탄데르 고객만족 데이터 탐색 대시보드** — 필터를 바꾸면 그래프·표가 실시간 갱신됨 |

`/dataviz`가 처음 열릴 때는 76,020행짜리 CSV(`정찬성/santander-customer-satisfaction/train.csv`)를 최초 1회 로드하느라 1~2초 정도 걸릴 수 있다(이후 요청부터는 캐시돼서 빠르다).

## 4. 서버 종료 방법

```powershell
# 1) 웹 서버 중지: uvicorn이 떠 있는 터미널에서 Ctrl+C

# 2) DB 컨테이너까지 완전히 내리려면 (데이터도 함께 삭제됨 — 주의)
docker compose down

# 데이터는 남기고 컨테이너만 멈추려면
docker compose stop
```

평소 작업할 때는 `docker compose stop`으로 컨테이너만 멈추고, 다음에 `docker compose start`(또는 `up -d`)로 재기동하는 편이 데이터를 유지하는 데 안전하다.

## 5. 트러블슈팅

### 5-1. `docker compose up -d`가 "port is already allocated" 에러

로컬에 이미 5432(또는 5555)를 쓰는 다른 Postgres 컨테이너가 떠 있다는 뜻이다.

```powershell
docker ps --format "{{.Names}}\t{{.Ports}}"
```

로 어떤 컨테이너가 포트를 쓰는지 확인하고, 남의 컨테이너라면 절대 내리지 말고 `.env`의 `POSTGRES_PORT`와 `DATABASE_URL`의 포트 번호만 비어있는 다른 값(예: 5556)으로 바꾼 뒤 다시 `docker compose up -d`.

### 5-2. `alembic upgrade head` 실행 시 `UnicodeDecodeError: 'cp949' codec can't decode ...`

`alembic.ini`에 한글(비-ASCII) 텍스트가 들어가면 한국어 Windows(cp949 로케일)에서 이 오류가 난다. `alembic.ini`는 항상 ASCII 텍스트만 유지해야 한다 — 이미 이 프로젝트의 `alembic.ini`는 ASCII로 정리돼 있으니, 직접 수정하지 않았다면 이 오류는 나지 않는다.

### 5-3. `/dataviz` 접속 시 500 에러 / `FileNotFoundError`

`.env`의 `SANTANDER_CSV_PATH`가 실제 CSV 파일을 못 찾는 경우다. 기본값은 `semi-backend/` 기준 상대경로 `../santander-customer-satisfaction/train.csv`다 — `정찬성/santander-customer-satisfaction/train.csv` 파일이 실제로 있는지 확인한다.

### 5-4. `pip install -e ".[dev]"` 실패

가상환경을 활성화하지 않고 실행했거나(`(.venv)`가 프롬프트에 안 보이면 `.venv\Scripts\activate` 먼저), Python 버전이 3.12 미만/3.15 이상인 경우가 대부분이다.

## 6. 한 번에 실행하는 전체 순서 (요약)

```powershell
cd 정찬성\semi-backend
.venv\Scripts\activate
docker compose up -d
alembic upgrade head
uvicorn app.main:app --reload
```

→ 브라우저에서 http://127.0.0.1:8000/dataviz 접속.
