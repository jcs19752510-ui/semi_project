### 겪은 문제와 해결

| 순서 | 문제 | 해결 |
|---|---|---|
| 1 | Render의 GitHub App이 `semi_project` 저장소에 접근 권한 없음(`toyo`만 연결돼 있었음) | GitHub → Render App 설정(`Repository access`)에서 `semi_project` 추가 |
| 2 | New Web Service 폼이 Go 프로젝트 기본값으로 채워짐 | Language를 Python 3로, Branch를 `SEMI_PROJECT`로, Build/Start Command를 프로젝트에 맞게 수정 |
| 3 | Root Directory(`정찬성/semi-backend`)가 "영문/숫자/`-_./`만 허용" 정규식에 걸려 거부됨(한글 폴더명 문제) | Root Directory는 비우고, Build/Start Command 안에서 `cd "정찬성/semi-backend" && ...`로 우회 |
| 4 | DB는 아직 연동하지 않기로 함(추후 Neon 등으로 연결 예정) | `DATABASE_URL`에 임시 placeholder(`postgresql+psycopg://unused:unused@localhost:5432/unused`)를 넣어 필수 필드 검증만 통과시킴, `Pre-Deploy Command`(`alembic upgrade head`)는 비워둠 — 실제 DB 연결 시 되돌려야 함 |
| 5 (2026-08-24) | v2 배포 직후 화면은 뜨는데 드롭다운/차트가 비어있고 `model-result` 500 발생 | 로컬에서는 `.env` 파일 부재로 `DATABASE_URL` 필수 필드 검증 실패가 원인이었음(`.env.example` 복사해 해결). Render 운영 서버는 직접 API(`curl`)로 실측한 결과 **정상 동작**하고 있었음 — 사용자가 본 오류는 Render 무료 인스턴스의 콜드스타트(최대 50초+) 타이밍과 겹친 것으로 결론 |
| 6 (2026-08-24) | 15분 무활동 시마다 슬립 → 재접속마다 지연 | Render 대시보드에서 Instance Type을 **Free → Starter(유료)**로 업그레이드해 상시 구동으로 전환(사용자가 직접 결제/설정 진행) |
